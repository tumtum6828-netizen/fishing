## งานล่าสุดและจุดเริ่มต่อ

คำขอล่าสุด: ตรวจสถานะโปรเจกต์ แล้วแยกเซฟโหมดทดสอบออกจากเซฟผู้เล่น ไม่แตะ gameplay หรือ schema เซฟ

ยังไม่ได้ทำและผู้ใช้อาจถามถึง: ภาพคอนเซปต์มีแถวพยากรณ์อากาศ 4 ช่องในป้ายสถานที่ แต่ระบบมีเฉพาะอากาศปัจจุบัน ยังไม่มีข้อมูลพยากรณ์ จึงคงเป็นนาฬิกา+ช่วงเวลาไว้; ชิปแต้มอนุรักษ์ไม่มีปุ่ม `+` เพราะยังไม่มีปลายทางให้เติมแต้ม; ไอคอนยังเป็นเวกเตอร์ ไม่ใช่ภาพวาดแบบในคอนเซปต์ ถ้าต้องการหน้าตาแบบนั้นจริงต้องทำไฟล์ PNG แล้ววางใน `public/assets/ui/` เหมือน `quest-board-v1.png`

รอบถัดมาแก้เรื่อง “ใส่ชุดแล้วดูเหมือนแปะไว้” ที่ `src/ui/avatarRenderer.ts`, `src/types/avatar.ts`, `src/data/avatarData.ts`

สาเหตุที่วัดได้จริง ไม่ใช่การเดา (วัดขนาดและกรอบวัตถุของ PNG ผ่าน canvas ในเบราว์เซอร์):

1. หมวกถูกยืด: ไฟล์ 1536x1024 (อัตราส่วน 1.5) แต่ placement เดิมสั่ง `width .72, height .23` บนกรอบ 1024x1536 ทำให้กว้างเกินจริงราว 39%
2. `placement` ที่ไม่ระบุ `y` ใช้ค่า `originY` เป็นค่าเริ่มต้น ซึ่งเท่ากับ 1 ทำให้ชิ้นถูกวางกึ่งกลางที่ขอบล่างของกรอบ เป็นบั๊กแฝงของค่าเริ่มต้น
3. เลเยอร์เครื่องแต่งกายไม่ได้รับ `tint` เดียวกับตัวละครฐาน สีจึงไม่เข้าโทนกัน

แก้แล้ว: `resolveLayerSize()` รองรับ 3 โหมด — ไม่ระบุ placement = ทับกรอบ 1:1, ระบุเฉพาะ `width` = คงสัดส่วนจริงของไฟล์, ระบุทั้งคู่ = ยืดตามสั่ง; ค่าเริ่มต้นของ x/y เป็น .5; เลเยอร์รับ tint เดียวกับฐาน; ปรับ placement ของหมวกเป็น `{x:.5, y:.06, width:.6}` และเสื้อเป็น `{x:.5, y:.534, width:.72}`

ตรวจแล้ว: build ผ่าน, `npm test` ผ่าน 15/15 (เพิ่มเทสต์ว่าเลเยอร์ต้องคงสัดส่วนจริงเสมอ), ดูบนเกมจริงทั้งหน้าโลกและหน้า “ตัวละคร”

ต่อมาเพิ่มระบบจุดยึด (anchor) เพราะฐานตัวละคร 8 แบบมีหัวคนละตำแหน่ง แต่ของสวมหัวใช้ค่าคงที่ค่าเดียว

- `AvatarTextureAsset` มีฟิลด์ `head: { cx, top, width }` วัดจากไฟล์ภาพจริงด้วย canvas ครบ 16 ค่า (8 ฐาน x 2 ท่า) อยู่ใน `src/data/avatarData.ts`
- `placement` รองรับโหมด `{ anchor: "head", widthScale, offsetY }` ชิ้นจะเกาะหัวจริงของฐานนั้นท่านั้น
- `avatarRenderer` คำนวณตำแหน่งและขนาดใหม่ทุกครั้งที่เปลี่ยนท่า ไม่ใช่คำนวณครั้งเดียวตอนสร้าง
- หมวกฟางเปลี่ยนเป็น `{ anchor: "head", widthScale: 1.31, offsetY: .048 }` ค่าเดียวใช้ได้ถูกต้องทั้ง 8 ฐาน

ตัวเลขที่วัดได้ ใช้อ้างอิงเวลาเพิ่มของใหม่:

- หัวต่างกันมาก: ขอบบน .003-.048, ความกว้าง .375-.500 (ต่างกัน 33%), กึ่งกลาง .449-.498
- ลำตัวเกือบเหมือนกันทุกฐาน: ไหล่ .351-.416, เอว .459-.487, เข่า .298-.314, พื้นเท้า .966-.976
- แปลว่า **ชุด/รองเท้า/ถุงมือ วาดชุดเดียวใช้ได้ทั้ง 8 ฐาน** ส่วนของสวมหัวต้องพึ่ง anchor

ต่อมาทำ validate เซฟตอนอ่านใน `src/services/save.ts`

- เพิ่ม `sanitizeSaveData()` ตรวจทีละฟิลด์ `readSaveData()` เรียกใช้ก่อนคืนค่า
- หลักการ: **ซ่อมทีละฟิลด์ ไม่ทิ้งทั้งก้อน** ฟิลด์ที่ผิดรูปหายไปเฉพาะฟิลด์นั้น ความคืบหน้าที่เหลืออยู่ครบ
- ตรวจลึก: ตัวเลขต้องเป็น finite number (`"5000"` และ `NaN` ถูกตัดทิ้ง), record ของตัวเลข, อาร์เรย์ของสตริง, `records` ต้องเป็นคู่ `[string, number]`, `weather` ต้องเป็นค่าที่มีจริง, `inventory.fish` เติมฟิลด์ที่ขาดเป็น 0 กัน NaN ลาม
- ตรวจแค่รูปร่าง (เป็น object ไหม): `aquarium`, `breeding`, `battle`, `dailyQuests`, `market`, `character`, `equippedFashion`, `quests` เพราะ service ของแต่ละระบบตรวจเนื้อในเองอยู่แล้ว จงใจไม่ไปตีความ schema ที่ยังไม่ได้ศึกษาครบ
- **ฟิลด์ที่ไม่รู้จักถูกส่งต่อตามเดิม** สำคัญมาก เพราะ `writeSaveData()` ทำ `{...readSaveData(), ...update}` ถ้าคัดเฉพาะฟิลด์ที่รู้จัก เซฟจากเวอร์ชันใหม่กว่าจะถูกลบทิ้งตอนเขียนกลับ

- **ไม่เปิดเผยปลาตำนานก่อนจับสำเร็จ** ระหว่างเย่อขึ้นแค่ "ฮุกติด! มีบางอย่างกินเหยื่อ" กับ "แรงตึงสาย N%" ไม่มีชื่อชนิด และ `commitHook()` ยังซ่อน `fishHud` ทั้งอันเมื่อเป็นปลาตำนาน ชื่อโผล่ครั้งแรกที่ `finishBattle` ตอนจับสำเร็จแล้วเท่านั้น
- **timer/listener ไม่ค้าง** `SHUTDOWN` ของ FishingScene เคลียร์ทั้ง timer และ keyboard listener ครบ และรอบนี้เพิ่ม `resultTimer` เข้าไปด้วย
- **ปุ่มออกจากฉาก** มี guard ให้กดได้เฉพาะตอน `state === "ready"` และหน้าผลปิดอยู่ ออกกลางเย่อไม่ได้
- **คีย์บอร์ด** ลูกศรเดินในแผนที่ และ SPACE ใช้เหวี่ยง/ฮุก/หมุนรอกได้ครบ
- **touch joystick** ลากด้วย pointer จริงแล้วตัวละครเดินตาม

### วิธีทดสอบแบบกำหนดผลได้ ไม่แตะ production

- เพิ่ม `tests/catch-pipeline.test.mjs` 7 เคส ทดสอบผลข้างเคียงของการจับที่ระดับข้อมูล และล็อกสัญญาสำคัญว่า `getTrashHookChance()` คืน 0 เสมอสำหรับเกรด good/excellent ทุกเหยื่อทุกสภาพอากาศ แปลว่าเหวี่ยงดี = ได้สัตว์น้ำแน่นอน
- ตอนทดสอบในเบราว์เซอร์ใช้วิธี override `Math.random` ใน console ให้อยู่ช่วง 0.85–0.99 ซึ่งมากกว่า trashChance (≤0.7) และ legendaryChance (≤0.4) เสมอ **เป็น harness ฝั่งเบราว์เซอร์ ไม่ได้แก้โค้ดเกม ไม่มีผลต่อ production build**
- ข้อควรรู้ถ้าทำซ้ำ: อย่า pin `Math.random` เป็นค่าคงที่ตัวเดียว เพราะ Phaser ใช้มันสร้าง UUID ของ texture จะได้ `Texture key already in use` แล้วฉากพัง ต้องให้ยังสุ่มอยู่ในช่วง

### ยังไม่ได้ตรวจ

- RiverScene ยังไม่ได้เข้าไปตกในรอบนี้ ตรวจเฉพาะชายฝั่ง
- ยังไม่ได้ทดสอบเส้นทาง "ขาย" และ "ปล่อยคืน" แบบเต็มวงจร ตรวจแต่ว่ากดหลังหน้าผลปิดแล้วไม่ให้รางวัลซ้ำ
- ยังไม่ได้ทดสอบบนมือถือจริง ใช้ pointer จริงในเบราว์เซอร์เดสก์ท็อปแทน

### งานถัดไปที่เสนอ

ทำสมุดบันทึกภาคสนามขั้น 3 ต่อ คือตารางนิเวศในหน้าสารานุกรม (`PlayerMenuScene.drawDex`) ซึ่งจะทำให้ตรวจการบันทึกช่องได้ด้วยตาโดยไม่ต้องเปิด console และตอนนี้ขั้น 2 ยืนยันแล้วว่าเขียนข้อมูลถูกชนิด

งานก่อนหน้าในโค้ดที่ตรวจพบ: ระบบตัวละครแยกชิ้น, ผูก preset กับฐานหน้าที่คงเดิมและบันทึก `baseVariant`, หน้าตู้เสื้อผ้ามีตัวอย่างยืน/เดิน พร้อมไฟล์ทดสอบตัวละครและตัวอย่างแอนิเมชัน

## ข้อควรระวังที่ผู้รับช่วงต้องรู้

2. แก้แล้ว: `seedPrototypeTestData()` เขียนลง key `-devtest` เท่านั้น เมื่อรัน dev และ `testDataVersion < 1` เซฟผู้เล่นไม่ถูกแตะอีก `npm run preview` และ build จริงใช้ key ผู้เล่นตามปกติ
3. เซฟ dev เป็นของทิ้งได้ ลบ key `-devtest` เพื่อทดสอบประสบการณ์เริ่มจากศูนย์ ห้ามเพิ่ม `TEST_DATA_VERSION` เพื่อเติมของซ้ำโดยไม่ตรวจผล

5. แม้แนวทางต้องการแยกฉาก แต่ `FishingScene`, `EquipmentScene`, `HubScene`, `DexScene` ยังอยู่ใน `src/main.ts`; อย่าเข้าใจว่าไฟล์ฉากตกปลาหาย และไม่ควรย้ายทั้งหมดระหว่างแก้งานเล็ก

7. วันที่ตรวจ `git status --short` แสดงไฟล์โปรเจกต์หลักเป็น untracked รวม src/docs/public จึงไม่มี baseline diff ที่เชื่อถือได้สำหรับไฟล์เหล่านั้น ห้าม clean/reset/ลบสิ่งที่ไม่รู้จัก และอย่า claim ว่ามี commit สำรองแล้ว
8. `dist/`, `node_modules/`, `tmp/`, `.codex-remote-attachments/` อยู่ในเครื่อง อย่ายกขึ้นมาเป็น source หลักหรือรวมเป็นงานส่งโดยไม่จำเป็น
9. ปัญหาในแชตเก่า เช่น เดินผ่านรั้ว การ์ดล้น หมวกแปะลอย เป็นรายการตรวจ regression ไม่ใช่หลักฐานว่าบั๊กยังอยู่ทุกข้อ
