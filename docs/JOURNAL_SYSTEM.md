# ระบบสมุดบันทึกภาคสนาม (ข้อเสนอออกแบบ)

ร่างวันที่ 4 กันยายน 2026 · **ขั้น 1-3 ทำแล้ว** (types/service/เทสต์, บันทึกตอนจับได้, ตารางนิเวศในสารานุกรม) ขั้น 4-5 ยังไม่ได้ทำ · อ่าน [GAME_PLAN.md](GAME_PLAN.md) และ [HANDOFF.md](HANDOFF.md) ประกอบ

## ปัญหาที่ออกแบบนี้แก้

นับจากโค้ดจริงในวันที่ร่าง:

| สิ่งที่มี | จำนวน |
|---|---|
| ชนิดสัตว์น้ำ | 7 + ปลาตำนาน 1 = **8** |
| แผนที่สำรวจ | **2** (ชายฝั่ง, แม่น้ำ) |
| คันเบ็ด | 3 |
| ระบบใหญ่ที่มีโค้ดแล้ว | **~12** (ตกปลา กระเป๋า สารานุกรม เควส รายวัน เลเวล ร้าน คราฟต์ ตลาด ตู้ปลา เพาะพันธุ์ ต่อสู้ แต่งตัว) |

**เกมมีระบบมากกว่ามีเนื้อหา** การเพิ่มระบบที่ 13 จะทำให้อาการหนักขึ้น ไม่ใช่ดีขึ้น

และมีของดีที่สร้างไว้แล้วแต่ผู้เล่นมองไม่เห็นเลย: `FISH_ENVIRONMENT_WEIGHTS` กำหนดว่าสัตว์แต่ละชนิดชอบแหล่งน้ำไหน ช่วงเวลาใด อากาศแบบใด แต่ทั้งหมดเป็นตัวคูณที่ทำงานเงียบๆ ข้างหลัง ผู้เล่นไม่มีทางรู้ ไม่มีทางใช้ และไม่มีเหตุผลต้องออกไปตกตอนกลางคืนหรือตอนฝนตก

ระบบเวลา อากาศ และแผนที่ จึงเป็นต้นทุนที่จ่ายไปแล้วแต่ยังไม่ได้ผลตอบแทน

## แนวคิด

> เปลี่ยนนิเวศจาก **ตัวคูณที่ซ่อนอยู่** ให้เป็น **ความรู้ที่ผู้เล่นค้นพบเองแล้วเอาไปใช้ได้**

ผู้เล่นเป็นนักสำรวจที่จดบันทึก ทุกครั้งที่ตกได้ เกมจะจดว่า *ได้ที่ไหน ตอนไหน อากาศเป็นยังไง* สมุดค่อยๆ เต็มขึ้น และเมื่อหลักฐานมากพอ สมุดจะสรุปนิสัยของสัตว์ชนิดนั้นให้ ซึ่งผู้เล่นเอาไปวางแผนการตกครั้งต่อไปได้จริง

นี่ทำให้เป้าหมายการเรียนรู้กลายเป็น *กลไกของเกม* ไม่ใช่การ์ดที่ต้องอ่าน

## ทำไมถึงเลือกระบบนี้

- **ได้เนื้อหาเพิ่มโดยไม่ต้องวาดภาพใหม่เลย** 8 ชนิดที่มีอยู่แปลงเป็น **108 ช่องให้ค้นพบ** (แหล่งน้ำที่ชนิดนั้นอยู่ได้ × 4 ช่วงเวลา × 3 สภาพอากาศ)
- ปลุกระบบเวลา/อากาศ/แผนที่ที่สร้างไว้แล้วให้มีความหมาย
- เป็นเหตุผลให้กลับไปแผนที่เดิมซ้ำ และเป็นเหตุผลให้อยากได้แผนที่ใหม่
- ตรงกับกลุ่มเป้าหมายเด็ก: ให้สังเกต ตั้งสมมติฐาน แล้วลอง
- ต้นทุนงานภาพต่ำมาก เป็นงาน UI กับข้อมูลเกือบทั้งหมด

## กติกา

### 1. บันทึกทุกครั้งที่ตกได้

ทุกการจับสำเร็จบันทึก 3 อย่าง: แหล่งน้ำ (coast/river) · ช่วงเวลา (morning/day/evening/night) · อากาศ (clear/cloudy/rain)

### 2. สมุดแสดงเป็นตาราง ไม่ใช่ตัวเลข

หน้าสารานุกรมของแต่ละชนิดมีตารางช่วงเวลา × อากาศ แยกตามแหล่งน้ำ ช่องที่เคยเจอจะสว่างขึ้น ช่องที่ยังไม่เจอเป็นเงา

**ห้ามแสดงค่าตัวคูณดิบ** ผู้เล่นควรอ่านว่า "เคยพบตอนเช้า ฟ้าโปร่ง ที่ชายฝั่ง" ไม่ใช่ "1.5x"

### 3. สรุปนิสัยเมื่อหลักฐานพอ

สมุดปลดล็อกคำสรุปเป็นขั้น โดยดึงจาก `FISH_ENVIRONMENT_WEIGHTS` จริง เช่น "ชอบออกหากินตอนเช้า" หรือ "ยิ่งฝนตกยิ่งเจอง่าย"

เกณฑ์ใช้**สัดส่วนของช่องทั้งหมด** ไม่ใช่ตัวเลขตายตัว เพราะชนิดที่อยู่ได้สองแหล่งน้ำมี 24 ช่อง ส่วนชนิดที่อยู่แหล่งเดียวมี 12 ช่อง ถ้าใช้เลขตายตัวชนิดที่อยู่แหล่งเดียวจะปลดล็อกง่ายเกินไป

| คำสรุป | สัดส่วน | 12 ช่อง | 24 ช่อง |
|---|---|---|---|
| ช่วงเวลา | 25% | 4 | 6 |
| สภาพอากาศ | 50% | 6 | 12 |
| แหล่งน้ำ | 75% | 9 | 18 |

ขั้นต่ำ 4 ช่องเสมอ ไม่ว่าสัดส่วนจะคำนวณได้เท่าไร

ความรู้ต้องมาจากการสังเกตของผู้เล่นก่อน เกมถึงยืนยันให้ ไม่ใช่บอกตั้งแต่แรก

### 4. เต็มการ์ดแล้วได้รางวัล

ค้นพบครบทุกช่องของชนิดหนึ่ง = เหรียญ + แต้มอนุรักษ์ + XP + ตราสัญลักษณ์ในสมุด

### 5. แผนที่ใหม่ปลดล็อกด้วยความรู้ ไม่ใช่ด้วยเลเวล

พื้นที่ถัดไปต้องการ "บันทึกครบ N ชนิด" หรือ "การ์ดเต็ม M ใบ" แทนการรอ XP สะสม การสำรวจจึงได้มาเพราะเรียนรู้ ไม่ใช่เพราะฟาร์ม

## โครงข้อมูล

```ts
// src/types/journal.ts
export type HabitatCell = {
  biome: FishingBiome;      // "coast" | "river"
  period: TimePeriod;       // morning | day | evening | night
  weather: WeatherId;       // clear | cloudy | rain
};

export type SpeciesLogEntry = {
  /** ช่องที่เคยพบ เก็บเป็นสตริง "biome:period:weather" เพื่อให้ JSON เล็กและเทียบง่าย */
  cells: string[];
  catchCount: number;
  /** worldDay ที่พบครั้งแรก ใช้แสดงในสมุด ไม่ใช้คำนวณอะไร */
  firstSeenDay?: number;
};

export type SpeciesLog = Record<string, SpeciesLogEntry>;
```

```ts
// src/services/journal.ts
export function recordCatch(speciesName: string, cell: HabitatCell): void;
export function readSpeciesLog(save?: SaveData): SpeciesLog;
export function getHabitatProgress(speciesName: string): { found: number; total: number };
export function isHabitatComplete(speciesName: string): boolean;
export function getUnlockedInsights(speciesName: string): string[];
```

```ts
// src/data/journalData.ts
export const MIN_CELLS_FOR_INSIGHT = 4;
export const INSIGHT_UNLOCK_FRACTIONS = { time: .25, weather: .5, biome: .75 };
export const HABITAT_COMPLETE_REWARD = { coins: 120, conservationPoints: 15, xp: 60 };
export const AREA_REQUIREMENTS: Record<string, { speciesLogged?: number; cardsComplete?: number }>;
```

จำนวนช่องทั้งหมดของแต่ละชนิดคำนวณจาก `FISH_ENVIRONMENT_WEIGHTS[name].biomes.length * 4 * 3` ไม่ต้องเขียนซ้ำในข้อมูล

## เซฟและความเข้ากันได้

เพิ่มฟิลด์เดียว `speciesLog?: SpeciesLog` ใน `SaveData`

- `sanitizeSaveData()` ต้องเพิ่ม validator: record ของ object ที่มี `cells` เป็นอาร์เรย์สตริงและ `catchCount` เป็นตัวเลข ทิ้งเฉพาะรายการที่เสีย
- **เซฟเก่าต้องไม่เริ่มจากศูนย์** ผู้เล่นที่มี `discoveredSpecies` อยู่แล้วควรได้ `catchCount: 1` และช่องว่างเปล่า พร้อมหมายเหตุในสมุดว่าบันทึกเก่าไม่ได้จดสภาพแวดล้อมไว้ ไม่ควรเดาช่องให้
- ทำ migration ครั้งเดียวแบบเดียวกับ `migrateCharacterAppearance()` และเขียนเทสต์คู่กัน

## ลำดับการสร้าง

แต่ละขั้นตรวจได้ด้วยตัวเอง ไม่ต้องรอขั้นถัดไป

1. **types + service + เทสต์** ยังไม่แตะ UI — พิสูจน์การนับช่อง การกันช่องซ้ำ และ migration จากเซฟเก่า
2. **บันทึกตอนจับได้** แก้จุดเดียวใน `resolveCatch` ตรวจด้วยการตกจริงแล้วดูค่าในเซฟ
3. **ตารางในสารานุกรม** งาน UI ล้วน
4. **รางวัลเมื่อการ์ดเต็ม** ผูกกับระบบรางวัลที่มีอยู่
5. **ปลดล็อกพื้นที่ด้วยเงื่อนไขสมุด** ทำท้ายสุด เพราะกระทบเส้นทางเล่นจริงมากที่สุด

ขั้น 1–3 ทำให้ระบบใช้งานได้จริงแล้ว ขั้น 4–5 เป็นการต่อเข้ากับ progression

## สิ่งที่จงใจไม่ทำ

- **ไม่เพิ่มระบบใหม่** เกมมีระบบเยอะเกินเนื้อหาอยู่แล้ว ตู้ปลา เพาะพันธุ์ ต่อสู้ ตลาด ยังใช้งานไม่เต็มที่ ควรถูกดึงมาเชื่อมกับสมุดมากกว่าถูกทิ้งไว้แล้วสร้างของใหม่
- **ไม่เพิ่มชนิดสัตว์น้ำในรอบนี้** ทำให้ 8 ชนิดเดิมน่าสนใจก่อน แล้วค่อยเพิ่ม การเพิ่มชนิดตอนนี้ได้แค่ตัวเลขในสารานุกรม ไม่ได้เกมที่ลึกขึ้น
- **ไม่แสดงตัวเลขความน่าจะเป็นให้ผู้เล่น** ผิดกลุ่มเป้าหมาย และทำลายความสนุกของการค้นพบ
- **ไม่เดาข้อมูลย้อนหลังให้เซฟเก่า** ช่องที่ไม่เคยจดไว้ต้องยังว่าง
